# 长视频识别与准确率验证

后端对超过 5 分钟的已提取音频自动分段，默认每段 300 秒。输入是 FFmpeg
提取的 16 kHz、单声道、16 位 PCM WAV，单次识别约 9.6 MB；有词级时间的引擎
会附带前后各 2 秒的上下文。识别时仅把当前音频段读入模型，一小时或更长的
音频不会作为一个 WAV 整体上传或一次解码到内存。整份 WAV 仍占用本地磁盘，
一小时约 115 MB，源视频和模型另外占空间。

各段成功后立即保存识别结果。失败、取消或进程退出后，重试使用相同音频和
识别设置时可复用已完成段。结果按原视频时间偏移拼接；重叠区用公共词串和
时间匹配去重，保留真实的重复说话。只有整段文本的云端接口采用非重叠上传，
其字幕精度仍受服务返回的时间信息限制。数字静音直接跳过，不送给模型。
普通模型、网络、认证或磁盘错误会中断任务，不作为静音跳过。

分段检查点位于应用数据目录的 `cache/transcripts/<任务ID>.parts/`；删除任务
时回收。改变模型、提示词、源语言或音频内容会使旧分段结果失效。临时音频
段在成功、失败或取消时清理；崩溃遗留的临时文件可能需要额外回收。

最终识别缓存也检查文本类型、有限且有效的时间轴及语言结构。损坏的最终稿
会隔离到同一任务的分段缓存目录，再从有效分段检查点恢复，不把损坏稿反复
当成已完成结果；隔离稿随任务删除一并清理。重建全局词时间轴时会补回分段
首词丢失的英文词间空格，并保留中文的连续书写。

云端段落损坏或缺少尾句时，如仍有完整文本，会保留全文并使用实际音频时长
生成整段字幕；这条恢复路径失去了精确句级时间信息，需要服务返回有效时间轴
才能恢复精确同步。无法确定时长时明确报错，不能把长音频编造成一秒字幕。

## 准确率设置

- 已知说话语种时，在字幕高级设置中明确选择“源语言”，可以减少误判。自动
  检测默认逐段进行，避免片头语种影响整部视频；确定是单语视频时可开启
  `transcriber.lock_detected_language`，首段语音之后固定检测语种。
- 当前客户端已有 medium、large-v3 模型选项。根据设备能力选择较大的模型
  做同一录音的对照评测；较大模型需要更多内存，CPU 识别可能明显慢于视频
  时长。长音频支持不代表能以实时速度完成，模型、设备和音质决定速度与质量。
- 默认 `beam_size: 5`。`condition_on_previous_text: false` 减少错误在后续
  解码窗口传播及重复循环；这种设置可能降低跨窗口措辞一致性，需要按真实
  录音对照，必要时恢复 true。
- `hotwords` 可填写人名、品牌及专有名词，`initial_prompt` 可填写简短背景。
  不要填入完整预期台词，提示内容可能被模型误输出。这些设置仅作用于本地
  faster-whisper，不能保证消除错字、漏字、口音或背景音乐干扰。
- 单个识别段允许 10–600 秒，可通过 `chunk_seconds` 调整；支持词级时间的
  引擎可用 `chunk_overlap_seconds` 调整 0–5 秒的边界上下文。

## 用真实录音评测

使用有权处理的访谈、课堂或会议录音，准备与识别内容相同的人工逐字稿，
先用软件完成原语言字幕，再运行：

```bash
cd video-subtitler
.venv/bin/python scripts/eval_transcript.py --language zh \
  --reference /path/to/人工逐字稿.txt --hypothesis /path/to/原语言字幕.srt
```

Windows 将解释器替换为 `.venv\Scripts\python.exe` 并将命令写成一行。
评测工具仅读取文件，不调用云端、不下载模型、不产生服务费用；支持 SRT、
转写 JSON 和纯文本。中文使用字符错误率 CER，空格分词语言另外报告 WER。
错误率越低越好，插入错误较多时可大于 1。评测归一化全半角、大小写、标点
符号和空白，中文统一简体；它衡量文字错误，字幕起止同步需另外对照音频。

至少分别记录清晰单人语音、普通对话、口音、背景音乐、长停顿和分段接缝。
对一小时以上视频，除整段 CER/WER 外，还应检查开头、中间、末尾和接缝处
是否漏段或重复。真实模型推理和人工逐字稿评测才能说明准确率变化；使用
模拟解码的长 WAV 测试只验证分段、时间轴、资源边界及恢复行为。
